# 演示案例

三份**故意写坏**的样本代码，以及对应的审查报告。用来直观展示这个技能能做什么、输出长什么样。

> ⚠️ 这些代码包含真实可触发的漏洞模式，**仅供本地演示**。不要部署、不要接入生产环境、不要复制到自己的项目中。

## 用法

任选一个样本，把代码贴给 AI 助手并说「审查这段代码」，对照同目录的 `report.md` 看输出是否一致。

| 目录 | 样本文件 | 预置问题 | 报告 |
| --- | --- | --- | --- |
| `python-flask/` | `orders_api.py` | SQL 注入、硬编码 JWT 密钥、IDOR、路径遍历、SSRF + 关闭证书校验、日志泄露 PII | [report.md](python-flask/report.md) |
| `java-spring/` | `OrderController.java` | SQL 注入、硬编码管理员令牌、退款接口无鉴权与越权、路径遍历、日志泄露 | [report.md](java-spring/report.md) |
| `vue-frontend/` | `CommentList.vue` | 存储型 XSS、DOM 型 XSS、Token 存 localStorage、开放重定向 | [report.md](vue-frontend/report.md) |

## 三份样本的侧重点不同

- **Python**：看后端数据层。重点是「加了参数绑定但仍不安全」——V-03 用了参数化查询，问题出在缺少归属校验
- **Java**：看越权与资损。V-03 是三个缺陷叠加（无鉴权 + 无归属校验 + 无金额校验），单看每个都不致命
- **Vue**：看前后端联动。单看 `localStorage` 只是 P2，叠加 XSS 后变成账号接管，报告的定级说明写了这个推导

## 一份好报告长什么样

对照 `report.md` 可以留意几个特征：

1. **每条结论都有行号和代码证据**，没有「建议加强输入校验」这种空话
2. **修复代码是可直接粘贴的**，不是伪代码
3. **区分「已确认」和「待确认」**，缺信息时给条件结论而不是硬判
4. **解释了等级为什么是这一级**，比如 Vue 的 V-03 写明「单独看是 P2，叠加上 XSS 才是真实危害」
5. **优先级有理由**，不是简单按 P0→P3 排
